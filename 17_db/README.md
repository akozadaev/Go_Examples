# 17. Работа с базами данных в Go

Материалы к двухчасовой лекции о реляционных и нереляционных СУБД, стандартном `database/sql`, PostgreSQL, транзакциях, SQL-инъекциях, GORM, sqlx, pgx, пулах соединений и миграциях.

- Полный текст: [lecture.md](lecture.md)
- `01`–`06` - SQLite и уровни доступа к данным;
- `07`–`11` - PostgreSQL, pgxpool и миграции;
- `go_message_handler_with_pessimistic_locking` - расширенный пример конкурентного обработчика с `FOR UPDATE SKIP LOCKED`.

Все модули рассчитаны на Go 1.26. Каждый каталог является самостоятельным Go-модулем и содержит собственную инструкцию запуска.

SQLite-примерам с `go-sqlite3` нужен C-компилятор и включённый CGO. PostgreSQL-примеры ожидают локальный сервер; конкретные имена баз и реквизиты учебного пользователя указаны в их README.

## Общий PostgreSQL для примеров 07–11

Собственный Dockerfile не требуется: корневой `compose.yaml` использует официальный образ PostgreSQL и при первом запуске создаёт все учебные базы и роли.

Из этого каталога выполните:

```bash
make up
make ps
```

После переходите в любой каталог `07`–`11` и запускайте `go run .`. Расширенный пример запускается так:

```bash
cd go_message_handler_with_pessimistic_locking
make migrate-up
make run
```

Контейнер доступен на `localhost:5432`. Для примеров `07`–`11` используются пользователь и пароль `ibs`, для обработчика сообщений - `messages`. Все строки подключения уже совпадают с этой конфигурацией.

Остановка без удаления данных:

```bash
docker compose stop
```

Удаление контейнера и учебных данных:

```bash
make down
```

Init-скрипты выполняются только при создании пустого volume. Если состав баз или ролей в них изменился, пересоздайте учебный volume командой `docker compose down -v`, а затем снова выполните `docker compose up -d`.
