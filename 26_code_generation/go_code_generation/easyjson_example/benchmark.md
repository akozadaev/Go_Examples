# Бенчмарк-тесты в Go с примерами кодогенерации

## Введение

Бенчмарк-тесты в Go — это специальный вид тестов, позволяющих измерять производительность кода. Они особенно полезны при сравнении различных реализаций (например, ручной vs сгенерированной) или при оценке влияния изменений на производительность. В контексте кодогенерации бенчмарки помогают убедиться, что сгенерированный код не только корректен, но и эффективен.

## Структура бенчмарк-теста

Бенчмарк в Go пишется как обычная функция с сигнатурой:

```go
func BenchmarkName(b *testing.B) {
    for i := 0; i < b.N; i++ {
        // Измеряемый код
    }
}
```

- `b.N` — количество итераций, которое `go test` автоматически подбирает для получения стабильных результатов.
- Все бенчмарк-функции должны находиться в файлах с суффиксом `_test.go`.

Запуск:
```bash
go test -bench=.
```

## Пример: Бенчмарк сериализации JSON с easyjson

В проекте реализованы бенчмарк-тесты для сравнения производительности стандартной библиотеки `encoding/json` и кодогенерированного кода с помощью `easyjson`.

### Исходные типы данных

В файле `easyjson_example/user.go` определены структуры `User` и `Profile`:

```go
// User представляет пользователя системы
type User struct {
    ID        int64     `json:"id"`
    Name      string    `json:"name"`
    Email     string    `json:"email"`
    CreatedAt time.Time `json:"created_at"`
    Tags      []string  `json:"tags"`
    Profile   *Profile  `json:"profile,omitempty"`
}

// Profile представляет профиль пользователя
type Profile struct {
    Bio      string            `json:"bio"`
    Settings map[string]string `json:"settings"`
    IsActive bool              `json:"is_active"`
    Score    float64           `json:"score"`
}
```

Структура `User` включает различные типы полей:
- Примитивные типы (`int64`, `string`, `bool`)
- Время (`time.Time`)
- Слайсы (`[]string`)
- Вложенные структуры (`*Profile`)
- Мапы (`map[string]string`)

### Генерация кода с easyjson

Для генерации методов маршалинга/анмаршалинга используется директива:

```go
//go:generate easyjson -all user.go
```

После выполнения `go generate` создаётся файл `user_easyjson.go` с оптимизированными методами `MarshalJSON` и `UnmarshalJSON`, не использующими reflection.

### Бенчмарк-тесты

Все бенчмарк-тесты находятся в файле `easyjson_example/benchmark_test.go`.

#### 1. BenchmarkEasyJSONMarshal

Тестирует производительность маршалинга через кодогенерированный метод `easyjson`:

```go
func BenchmarkEasyJSONMarshal(b *testing.B) {
    user := &User{
        ID:        1,
        Name:      "Иван Иванов",
        Email:     "ivan@example.com",
        CreatedAt: time.Now(),
        Tags:      []string{"developer", "golang"},
        Profile: &Profile{
            Bio:      "Go разработчик",
            Settings: map[string]string{"theme": "dark", "lang": "ru"},
            IsActive: true,
            Score:    95.5,
        },
    }

    b.ResetTimer()
    for i := 0; i < b.N; i++ {
        _, _ = user.MarshalJSON()
    }
}
```

**Особенности:**
- Использует кодогенерированный метод `MarshalJSON()` из `user_easyjson.go`
- Измеряет только время выполнения маршалинга (используется `b.ResetTimer()`)
- Тестирует сложную структуру с вложенными объектами и массивами

#### 2. BenchmarkStandardJSONMarshal

Тестирует производительность стандартной библиотеки `encoding/json`:

```go
func BenchmarkStandardJSONMarshal(b *testing.B) {
    user := &User{
        ID:        1,
        Name:      "Иван Иванов",
        Email:     "ivan@example.com",
        CreatedAt: time.Now(),
        Tags:      []string{"developer", "golang"},
        Profile: &Profile{
            Bio:      "Go разработчик",
            Settings: map[string]string{"theme": "dark", "lang": "ru"},
            IsActive: true,
            Score:    95.5,
        },
    }

    b.ResetTimer()
    for i := 0; i < b.N; i++ {
        _, _ = json.Marshal(user)
    }
}
```

**Особенности:**
- Использует стандартную функцию `json.Marshal()` с reflection
- Тестирует ту же структуру данных, что и `easyjson` вариант
- Используется для сравнения производительности

#### 3. BenchmarkEasyJSONUnmarshal

Тестирует производительность анмаршалинга через кодогенерированный метод:

```go
func BenchmarkEasyJSONUnmarshal(b *testing.B) {
    jsonData := []byte(`{"id":1,"name":"Иван Иванов","email":"ivan@example.com","created_at":"2024-01-01T00:00:00Z","tags":["developer","golang"],"profile":{"bio":"Go разработчик","settings":{"theme":"dark","lang":"ru"},"is_active":true,"score":95.5}}`)
    var user User

    b.ResetTimer()
    for i := 0; i < b.N; i++ {
        _ = user.UnmarshalJSON(jsonData)
    }
}
```

**Особенности:**
- Использует кодогенерированный метод `UnmarshalJSON()` из `user_easyjson.go`
- Тестовые данные предподготовлены как JSON-байты
- Измеряет скорость парсинга JSON в структуру

#### 4. BenchmarkStandardJSONUnmarshal

Тестирует производительность стандартной библиотеки при анмаршалинге:

```go
func BenchmarkStandardJSONUnmarshal(b *testing.B) {
    jsonData := []byte(`{"id":1,"name":"Иван Иванов","email":"ivan@example.com","created_at":"2024-01-01T00:00:00Z","tags":["developer","golang"],"profile":{"bio":"Go разработчик","settings":{"theme":"dark","lang":"ru"},"is_active":true,"score":95.5}}`)
    var user User

    b.ResetTimer()
    for i := 0; i < b.N; i++ {
        _ = json.Unmarshal(jsonData, &user)
    }
}
```

**Особенности:**
- Использует стандартную функцию `json.Unmarshal()` с reflection
- Тестирует парсинг того же JSON, что и `easyjson` вариант
- Позволяет сравнить производительность парсинга

### Запуск бенчмарков

#### Запуск всех бенчмарков

```bash
cd easyjson_example
go test -bench=.
```

#### Запуск с анализом памяти

Для получения информации об аллокациях памяти:

```bash
go test -bench=. -benchmem ./easyjson_example
```

#### Запуск через Makefile

В проекте предусмотрена команда для запуска бенчмарков:

```bash
make bench
```

Это выполнит:
```bash
go test -bench=. -benchmem ./easyjson_example
```

#### Запуск конкретного бенчмарка

Для запуска только тестов маршалинга:

```bash
go test -bench=Benchmark.*Marshal -benchmem ./easyjson_example
```

Для запуска только тестов анмаршалинга:

```bash
go test -bench=Benchmark.*Unmarshal -benchmem ./easyjson_example
```

### Ожидаемые результаты

При запуске бенчмарков вы должны увидеть результаты примерно следующего вида:

```
BenchmarkEasyJSONMarshal-8          1321542        891 ns/op        512 B/op        5 allocs/op
BenchmarkStandardJSONMarshal-8       278478       4290 ns/op       2048 B/op       15 allocs/op
BenchmarkEasyJSONUnmarshal-8         985432       1215 ns/op        384 B/op        3 allocs/op
BenchmarkStandardJSONUnmarshal-8     456789       2634 ns/op       1536 B/op       12 allocs/op
```

**Анализ результатов:**

1. **Производительность:** Кодогенерированный `easyjson` обычно в 3-5 раз быстрее стандартной библиотеки
2. **Память:** `easyjson` выделяет значительно меньше памяти (меньше `B/op`)
3. **Аллокации:** Количество аллокаций (`allocs/op`) у `easyjson` заметно меньше

### Почему easyjson быстрее?

1. **Отсутствие reflection:** Стандартная библиотека использует reflection для определения типов полей во время выполнения. `easyjson` генерирует статический код, который работает напрямую с полями структуры.

2. **Оптимизированные буферы:** `easyjson` предварительно выделяет буферы нужного размера и переиспользует их.

3. **Специализированный код:** Генерированный код оптимизирован именно для конкретной структуры, без универсальных решений.

4. **Меньше аллокаций:** Избегаются промежуточные аллокации, которые возникают при использовании reflection.

### Рекомендации по написанию бенчмарков

1. **Используйте `b.ResetTimer()`** для исключения времени инициализации из измерений. В представленных тестах это используется для исключения времени создания структуры `User`.

2. **Используйте одинаковые входные данные** для справедливого сравнения. Оба варианта (стандартный и easyjson) тестируются на одинаковых структурах `User`.

3. **Запускайте с `-benchmem`** для анализа использования памяти:
   ```bash
   go test -bench=. -benchmem
   ```

4. **Запускайте на "чистой" машине** без фоновых нагрузок для стабильных результатов.

5. **Повторяйте запуски** несколько раз для получения средних значений. Go автоматически подбирает количество итераций, но можно запустить несколько раз:
   ```bash
   go test -bench=. -count=5
   ```

6. **Используйте профилирование** для глубокого анализа:
   ```bash
   go test -bench=. -cpuprofile=cpu.prof -memprofile=mem.prof
   ```

### Особенности реализации

В данных бенчмарк-тестах:

- **Инициализация данных:** Структура `User` создаётся один раз перед циклом, что правильно для измерения производительности самого маршалинга/анмаршалинга.

- **Использование `b.ResetTimer()`:** Важно для исключения времени инициализации из результатов измерения.

- **Тестовые данные:** JSON для анмаршалинга предподготовлен как байтовый массив, что корректно, так как мы измеряем именно скорость парсинга, а не создания JSON.

- **Игнорирование ошибок:** Используется `_` для игнорирования результатов, так как в бенчмарках нас интересует только скорость выполнения, а не обработка ошибок.

### Заключение

Бенчмарк-тесты в данном проекте демонстрируют значительное преимущество кодогенерированного кода (`easyjson`) над стандартной библиотекой `encoding/json`:

- **Скорость:** В 3-5 раз быстрее маршалинг и анмаршалинг
- **Память:** Значительно меньшее потребление памяти
- **Аллокации:** Меньше аллокаций объектов

Это делает `easyjson` отличным выбором для высоконагруженных приложений, где производительность JSON-сериализации критична. Регулярный запуск бенчмарков помогает:

- Убедиться, что кодогенерация не вносит регрессий
- Сравнивать производительность до и после оптимизаций
- Выбирать оптимальные инструменты для конкретных задач
- Автоматизировать проверку производительности в CI/CD

Используйте бенчмарки как часть вашего workflow при работе с кодогенерацией!
