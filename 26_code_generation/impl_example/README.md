# Генерация заготовок с `impl`

## Назначение примера

Если интерфейс содержит много методов, ручное переписывание всех сигнатур для нового типа занимает время и создаёт риск опечатки. Компилятор обнаружит отсутствие метода, но не напишет заготовки реализации.

Этот пример показывает использование [`impl`](https://pkg.go.dev/github.com/josharian/impl) для типа `FileLogger` и интерфейса `Logger`.

- **Решаемая проблема:** быстро и без ошибок перенести сигнатуры всех методов интерфейса в реализацию.
- **Что генерируется:** заготовки методов с правильными receiver, параметрами и результатами; тела содержат `panic("not implemented")`.
- **Когда полезно:** первоначальная реализация крупных интерфейсов, создание адаптеров и обновление типа после расширения интерфейса.

`impl` не генерирует бизнес-логику. Разработчик обязан заменить заглушки корректной реализацией, обработать ошибки и проверить интерфейсные инварианты. В отличие от `stringer` и `easyjson`, инструмент обычно выводит фрагмент в stdout, а не сопровождает generated-файл автоматически.

## Файлы

| Роль | Файл относительно корня `go_code_generation` |
|---|---|
| Исходный интерфейс `Logger` | `impl_example/logger.go` |
| Receiver и доработанная реализация | `impl_example/file_logger.go` |
| Демонстрация | `cmd/impl/main.go` |
| Runtime-результат | `app.log` в текущем рабочем каталоге |

## Установка и запуск генератора

```bash
go install github.com/josharian/impl@latest
impl 'recv *FileLogger' github.com/akozadaev/go-code-generation/impl_example.Logger
```

Для production-среды закрепляют конкретную версию. `impl` выводит методы в stdout и **не создаёт автоматически** `file_logger.go`. Для предварительного просмотра результат можно перенаправить во временный файл:

```bash
impl 'recv *FileLogger' github.com/akozadaev/go-code-generation/impl_example.Logger > /tmp/file_logger_stubs.go
```

Это только фрагмент с методами, не обязательно готовый файл пакета. В данном примере заготовки перенесены и вручную реализованы здесь:

```text
impl_example/file_logger.go
```

Инструмент знает сигнатуры `Log`, `Logf`, `Error`, `Errorf`, но не знает, как записывать файл и обрабатывать ошибки. Поэтому `file_logger.go` не является полностью generated-файлом, не имеет `DO NOT EDIT` и хранится в Git.

Для compile-time проверки полезно добавить:

```go
var _ Logger = (*FileLogger)(nil)
```

## Запуск примера

```bash
go run ./cmd/impl
go test ./impl_example
go vet ./impl_example
```

Демонстрация создаёт `FileLogger` с относительным именем `app.log`. Файл появляется в каталоге, из которого запущена команда. Заглушка, которая компилируется, ещё не является корректной реализацией: после `impl` необходимо определить обработку ошибок, конкурентность и предметную семантику.
