# Собственный AST-генератор мапперов

## Назначение примера

В прикладном коде часто приходится преобразовывать внутренние модели в DTO и обратно. Ручные мапперы типобезопасны, но содержат много однообразных присваиваний и должны синхронно изменяться вместе со структурами.

Этот пример показывает не готовую стороннюю библиотеку, а устройство собственного генератора на основе Go AST.

- **Решаемая проблема:** автоматически создавать повторяющиеся типобезопасные преобразования model ↔ DTO.
- **Что генерируется:** функции преобразования отдельных значений и слайсов, включая поддержанные специальные конверсии `time.Time` ↔ RFC3339-строка.
- **Когда полезно:** при большом числе похожих моделей и DTO, когда их формы известны во время сборки и ручное сопровождение мапперов становится дорогим.
- **Зачем здесь AST:** `go/parser` и `go/ast` позволяют надёжно прочитать объявления типов, поля и теги как структуру языка, а не искать их регулярными выражениями в тексте.

Пример демонстрирует полный цикл: генератор читает структуры через `go/parser` и `go/ast`, сопоставляет поля, выполняет `text/template`, форматирует код через `go/format` и записывает `.go`-файл. Это учебная реализация с явно перечисленными ниже ограничениями.

## Генератор и демонстрация

- `cmd/mapper/main.go` — генератор. Требует `-type`, `-dto`, `-output` и список входных Go-файлов.
- `cmd/mapper-demo/main.go` — не генератор, а программа, вызывающая уже созданные функции.
- `mapper_example/helpers.go` — ручные функции преобразования времени, не generated-файл.

## Точные входы и выходы

| Типы | Исходный файл | Файл с директивой | Выходной файл |
|---|---|---|---|
| `User`, `UserDTO` | `mapper_example/user.go` | `user.go` | `mapper_example/user_mapper_gen.go` |
| `Product`, `ProductDTO` | `mapper_example/product.go` | `product.go` | `mapper_example/product_mapper_gen.go` |
| `Order`, `OrderDTO` | `mapper_example/order.go` | `order.go` | `mapper_example/order_mapper_gen.go` |
| `OrderItem`, `OrderItemDTO` | `mapper_example/order.go` | `order_item.go` | `mapper_example/order_item_mapper_gen.go` |

Для `OrderItem` директива вынесена в `order_item.go`, но анализирует `order.go`, где реально объявлены обе структуры.

## Директивы

Пример для `User`:

```go
//go:generate go run ../cmd/mapper/main.go -type=User -dto=UserDTO -output=user_mapper_gen.go user.go
```

Остальные фактические команды:

```bash
go run ../cmd/mapper/main.go -type=Product -dto=ProductDTO -output=product_mapper_gen.go product.go
go run ../cmd/mapper/main.go -type=Order -dto=OrderDTO -output=order_mapper_gen.go order.go
go run ../cmd/mapper/main.go -type=OrderItem -dto=OrderItemDTO -output=order_item_mapper_gen.go order.go
```

Внешний CLI устанавливать не нужно: `go run` собирает генератор из исходника текущего модуля.

## Генерация

Из корня `go_code_generation`:

```bash
go generate ./mapper_example
```

Из `mapper_example`: `go generate`. Просмотр без записи:

```bash
go generate -n ./mapper_example
```

`go generate` запускает команды в каталоге пакета, поэтому имена из `-output` создаются непосредственно в `mapper_example`.

## Содержимое generated-файлов

Для каждой пары создаются:

- преобразование модели в DTO, например `(*User).ToUserDTO()`;
- обратная функция, например `UserDTOToUser`;
- преобразование слайса моделей;
- обратное преобразование слайса DTO;
- поддержанные специальные конверсии, включая `time.Time` ↔ RFC3339-строку.

Файлы начинаются с `// Code generated by mapper generator. DO NOT EDIT.` и полностью перезаписываются. Правки вносят в модели, теги, шаблон или `cmd/mapper/main.go`.

## Демонстрация и проверка

После генерации:

```bash
go run ./cmd/mapper-demo
go test ./mapper_example
go vet ./mapper_example
```

Демонстрация использует `User`, `Product`, `Order`, вложенные `OrderItem` и слайсы.

## Ограничения учебной реализации

- Сопоставление основано преимущественно на синтаксисе, а не полной информации `go/types`.
- Поддержаны не все `ast.Expr`, generic-типы и alias-импорты.
- Production-версии нужны точные diagnostics, атомарная запись, golden-тесты и compilation tests.
- Неизвестный тип должен приводить к понятной ошибке, а не к генерации строки `unknown`.
